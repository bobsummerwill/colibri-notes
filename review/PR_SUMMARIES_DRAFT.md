# Draft PR summaries (not submitted)

Written by the final stack check; starting points for the three PR descriptions. Target branch upstream: `dev`.

## PR #0 — `pr0/dsv4-fixes`

deepseek-v4: CUDA backend and GPU-tier correctness fixes. 13 commits on dev 7b55a9b3. (1) Host-to-device uploads (decode mirrors, in-place refills, expert and hash tables, RoPE tables, TP2 bank) are now ordered on the compute stream through a new h2d() helper; before, legacy-stream copies could race the fused decode MoE and make greedy decode drift. (2) Failed allocations no longer leave a stale CUDA error that fails the next unrelated launch: the expert-bank create clears it, and alloc_ok() covers buf(), upload(), activation_create and the KV ring and compressed-KV appends (F27). (3) A decode mirror slot whose upload failed is rolled back, and the card counts as full until the next probe; before, dead entries pushed GPU decode onto the CPU (F4, F37). (4) The prefill expert bank is freed on every generate() exit and at engine close (F10, F11). (5) Speculative verify and replay batches stay off the GPU prefill bank (F2). (6) GPU prefill refuses a layer whose router bias has no mirror instead of routing it without the bias (F23). (7) Dual-loader lanes are finished on every MoE exit, removing a stack use-after-return and lease leaks (F26). (8) dsv4_cuda_shutdown zeroes each device slot, so a re-init cannot reuse freed buffers (F28). (9) dsv4_cuda_device_unified is exported from the Windows DLL, with a new loader parity test (F1). (10) make dsv4-cuda-test now passes on generic builds: the batched-MoE test skips before its 3.2 GiB bank (F49), and the sparse-batch attention step skips while it is a stub. (11) Docs and comments give the real sizes: 12.75 MiB per mirror, a 3264 MiB bank. There are no new switches; behaviour changes only on failure paths, with COLI_CUDA_MOE_BATCH=1 plus speculative decoding, or in which stream uploads run on. Tests: the parity test, two source-level bank tests, and the updated CUDA tests. make check gives 2378 OK; the CUDA sm_86 build has no warnings; make dsv4-cuda-test passes on an RTX 3090.

## PR #1 — `pr1/reap-prefill` (stacked on PR #0)

deepseek-v4: batched GPU prefill for expert-pruned (REAP) checkpoints, and faster generic kernels. 7 commits on the fixes above. (1) The batched prefill MoE (COLI_CUDA_MOE_BATCH=1) now takes 1..256 routed experts. The bank is sized by dsv4_cuda_expert_bank_slots: 132 slots, 1683 MiB, for REAP-150B on generic builds; DeepGEMM builds keep 256. (2) Pruned, hash and missing-bias-mirror layers route on the CPU bf16 router inside the batched path, bit-identical to the CPU union (F2, F12, F22, F23, F31). A second bank that did not fit is retried at the next prefill. (3) The default DSV4_CUDA_VRAM_RESERVE_MB with the bank on is sized from the model at engine open: bank x1 or x2, plus 600 MiB headroom, plus 64 mirrors. That is 4681 MiB for 256 experts and 3100 for 132; it is only the headroom below 32 live mirrors. It uses the new dsv4_cuda_expert_bank_slot_bytes (F7, F8). (4) A bit-identical expert-major fp4 kernel for the generic batched MoE, on by default (DSV4_MOE_EXPERT_MAJOR=0 turns it off; DSV4_MOE_EM_TB=2|3|4|6; _VERIFY=1 cross-checks). (5) A bit-identical warp-per-row kernel for short fp8 dense batch matmuls (DSV4_MM_WARP: auto means I <= 1024, 1 means every fp8 shape whose I is a multiple of 256, 0 means never; _VERIFY=1). (6) V4_MOE_BATCH_PROF=1 prints a per-chunk time split. (7) Docs: REAP prefill on a 3090 (1,992 tokens 220.5 s -> 69.1 s; ~3,000 tokens 334.4 s* -> 105.8 s; one run per cell, with a footnote) and decode per prompt. Everything except the bit-identical kernels is behind COLI_CUDA_MOE_BATCH=1, which stays off by default. Tests: test_v4_bank_pair.c, test_dsv4_bank_bytes_cuda.c, test_dsv4_generic_bitwise_cuda.c, the lifecycle source test and the parity test. make check gives 2379 OK; the CUDA sm_86 build has no warnings; make dsv4-cuda-test passes on an RTX 3090.

## PR #2 — `pr2/two-gpu-decode` (stacked on PR #1)

deepseek-v4: two-GPU decode and VRAM-first expert lookups. 8 commits on the REAP prefill series. (1) DSV4_CUDA_PIN_CAP_GB sets the cap on page-locked expert slabs; the default stays 20 GiB and the value is clamped (F57). (2) V4_SERVE_STATS_LOG=1 prints per-turn decode stats and decode-MoE counters (F34, F35). (3) V4_GPU_RESIDENT_FIRST=1 serves experts that are already mirrored in VRAM without a store lookup. The routing history and the dashboard still see those experts (F6), RAM pins skip them (F24), and a failed attach falls back through the loader lanes (F25). (4) The mirror cache's growth-guard state is per cache, with one shared LRU clock. (5) Mirror caches keep their VRAM reserve between probes, and failed uploads are dropped (F16, final form of F4 and F37). This is the one behaviour change with every switch off: an explicit or no-bank reserve is now kept once 8 mirrors are live. (6) DSV4_CUDA_PEER_DEVICE=N adds a second mirror pool on GPU N, configured by DSV4_CUDA_PEER_MIRRORS and DSV4_CUDA_PEER_RESERVE_MB. GPU N is probed before it is touched, a failed init is rolled back, and the attach is tiered (F3, F5, F13-F15, F32). (7) DSV4_CUDA_PEER_COMPUTE, default 1 when a pool exists, runs the peer's experts on the peer, bit-identically; a failing peer is latched off (F17-F21, F38). DSV4_CUDA_PEER_FAULT is a test hook for that. (8) Docs: decode on 2x RTX 3090 with NVLink went 2.78 -> 2.84 -> 3.32 -> 3.87 tok/s, marked to be re-measured. All new features are off unless set. Tests: test_dsv4_peer_init_cuda.cu, test_dsv4_peer_moe_cuda.c (both first in dsv4-cuda-test; they skip without two GPUs that have peer access), test_v4_peer_init_source.py, and a VRAM-first store test in test_deepseek_v4.c. make check gives 2384 OK; the CUDA sm_86 build has no warnings; make dsv4-cuda-test passes on two RTX 3090s.
