## Summary

Two-GPU decode for DeepSeek V4 on CUDA, plus VRAM-first expert lookups. 11 commits on top of #2401.

All new behaviour is opt-in:
- `V4_GPU_RESIDENT_FIRST=1`: an expert already mirrored in VRAM is computed from the mirror without a RAM-store lookup. The store still records the routing (history, HITS, heat), and its RAM pin ranking leaves mirrored experts out, so RAM holds experts that are not in VRAM. Useful on one GPU too.
- `DSV4_CUDA_PEER_DEVICE=N`: a second mirror pool on GPU N. It needs peer access both ways (e.g. NVLink); without it the pool stays off with a warning, and decode runs on the primary GPU. `DSV4_CUDA_PEER_COMPUTE` (default 1) runs the experts mirrored there on that GPU, bit-identically. GPU N is probed before it is touched, and a failed init is rolled back.
- `DSV4_CUDA_PIN_CAP_GB` caps the page-locked expert slabs (default unchanged, 20 GiB).
- `V4_SERVE_STATS_LOG=1` prints per-turn decode stats and decode-MoE counters.

Two changes apply with every switch off:
- **The mirror growth guard moves into each cache** (the peer pool has its own card, free VRAM and reserve) and keeps #2401's rule. One difference from #2401: the bank-sized default keeps its 64-mirror probe margin below 32 live mirrors too, where that default is only the 600 MiB headroom (#2401 gives it none there). That phase lasts until the cache holds 32 mirrors and only matters on a card too small for the bank; `docs/deepseek-v4.md` says so. A failed mirror upload rolls its slot back instead of leaving a dead entry.
- **A sticky CUDA fault no longer fails every later request.** A launch failure (e.g. a trap on the peer GPU) is sticky for the process's whole CUDA context, device 0 included. The engine now latches CUDA off for the process (`dsv4_cuda_lost()`):
  - mirror lookups miss;
  - the decode MoE takes host copies;
  - the attention's grouped `wo_a` matvec falls back to the CPU;
  - a failed decode block names its stage and keeps the inner error.

  The faulted request and every later one complete on the host, at host speed, until restart.

**REAP-150B**, `COLI_CUDA_MOE_BATCH=1`, six 300-token answers per sample:

Every answer is byte-identical to the base's. With every new switch off, this PR measured 0.999x dev (final11). VRAM-first alone, on one GPU, measured 1.021-1.030x (final6).

**Full DeepSeek-V4-Flash** (new; final22, x2 each), two prompts (1,992 and 3,005 tokens):

**Fault test** (final13; repeated in final21): `DSV4_CUDA_PEER_FAULT=3000:sticky` injects a sticky fault on the peer GPU at the 3000th pass, in a server answering the same six prompts. All six requests complete with 300 tokens each, on the host after the fault, with no hang. Before the latch, every request after the fault failed until restart.
